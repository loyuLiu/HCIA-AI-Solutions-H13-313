## 停止服务

- 用户要求停服。做法：`netstat -ano | grep :8787` 找 LISTENING 的 PID →
  PowerShell `Stop-Process -Id <pid> -Force`（Git Bash 下 `taskkill //PID` 参数会被路径转换搞坏，别用）。
- 停服后建议跑一次 `better-sqlite3` 打开 db 并 `PRAGMA wal_checkpoint(TRUNCATE)` 再 close，
  把 `-wal`/`-shm` 合并回 `hcia.db`（本次 4KB→32KB），这样单文件备份才是完整的。
- 重启：双击 `启动平台.bat` 或 `node server.js`。

## 新增：关闭平台.bat

- 与 `启动平台.bat` 同目录。双击即可停服；支持传端口参数 `关闭平台.bat 9000`。
- 逻辑：`netstat -ano | findstr ":端口" | findstr LISTENING` 取第 5 列 PID →

- 关键坑：WAL 归档的临时 js 若放 `%TEMP%`，`require('better-sqlite3')` 会按脚本目录解析而找不到

- 沙箱限制：cmd.exe 在本环境被整体禁用（连纯 ASCII 的 bat 都无法通过 Start-Process 执行），
  所以 .bat 无法端到端自动化测试，只能用 PowerShell 原生等价逻辑验证（Get-NetTCPConnection + Stop-Process）。

## 新增：pm2 进程管理（替代手动启停）

- 需求：用户要用 pm2 管理服务的启动/停止。
- 交付物（均在 `hcia-platform/` 或工作区根目录）：
  1. `hcia-platform/ecosystem.config.js`（pm2 启动配置）：name=hcia-platform，script=server.js，fork 单实例，
     autorestart=true，watch=false，kill_timeout=8000，env PORT=8787/HOST=0.0.0.0。
  2. `hcia-platform/pm2/` → 改为装在本项目：在 hcia-platform 执行 `npm install pm2`（v7.0.4，装到本项目 node_modules，复用受管 node）。
  3. 工作区根目录 `pm2-管理.bat`：用 `%~dp0hcia-platform` 自动定位目录（避免中文路径编码乱码），
     `where node` 失败则回退受管 node 路径到 PATH，首次自动 `npm install pm2`，
     参数 start/stop/restart/logs/status/delete/save 映射到 pm2 命令，无参默认 start。
  4. 增强 `server.js` 关闭逻辑：`SIGINT`/`SIGTERM` 触发 `wal_checkpoint(TRUNCATE)` 再 `db.close()`，
     保证 pm2 stop 后 `data/hcia.db` 为单文件完整备份（旧版只 `db.close()`，WAL 不一定截断）。
- 验证：单次 Bash 调用内跑通 start（HTTP 200）→ stop（状态 stopped、端口释放、hcia.db 单文件完整、无 WAL 残留）。
- 坑：本沙箱两次 Bash 调用之间会回收 pm2 守护进程，导致跨调用 `pm2 stop` 报 "not found"，这是沙箱限制，
  真实机器上 pm2 守护进程常驻、bat 双击启动/停止正常，无需担心。
- pm2 用法：`pm2 start ecosystem.config.js` / `pm2 stop hcia-platform` / `pm2 logs hcia-platform` / `pm2 save` + `pm2 startup`（开机自启）。

## 修复：练习模式进度不保存（断点续练）

- 问题根因：`app.js` 里 `S`（`list/pos/answers/mode`）纯内存变量，刷新或换浏览器即丢；
  持久化到 localStorage + 云端的只有 `store`（stat/wrong/fav/records/theme）。
- 方案：在 `store` 新增 `session` 字段 `{mode,title,pos,ids[],answers,savedAt}`，
  新增 `saveSession() / clearSession() / restoreSession()`：
  - `saveSession()` 只在 `S.mode === "practice"` 时落盘（考试不落盘，计时交卷不宜中断恢复）。
  - `restoreSession()` 会校验 `ids` 全部能在题库里解析到，解析不到（题库变更）就作废会话。
- 保存点（共 6 处）：`startList()`、`submitAnswer()`、`jump`/`prev`/`next`、键盘 ←/→/Enter。
  「完成练习」`finish` 调 `clearSession()`；「退出」保留 session 以便续练。
- 恢复入口：
  - 启动时 `restoreSession()` 成功则 `view="practice"` 并 toast 提示题号；
  - 练习设置页新增「继续上次练习」卡片（继续练习 / 放弃进度）；
  - 首页「快速开始」卡片内新增续练小条。
- 云端同步：`auth.js` 的 `applyServerData` 现在同步 `session`，并按 `savedAt` 时间戳取本地/云端较新的一份
  （最后写入者胜），避免离线答题后被旧云端数据覆盖；恢复后若停在首页则自动进入练习。
- 关闭页面兜底：`auth.js` 增加 `beforeunload` + `navigator.sendBeacon` 立即推送，
  防止 800ms 防抖窗口内关页面丢最后一次操作。
- 新增测试 `hcia-platform/test-session.js`（jsdom 端到端，自带拉起/关闭 server.js），
  覆盖：练习落盘 → 模拟刷新恢复（题号/已答数/题卡标记）→ 首页续练 → 退出后续练 → 放弃进度 → 服务端 session 往返。
  运行：`NODE_PATH=C:/Users/cheny/.workbuddy/binaries/node/workspace/node_modules node test-session.js`，22 项全通过。
- **重要坑**：同一文件上的多次 Edit 并行下发会静默丢失（本次丢了 3 处：启动恢复、startList、submitAnswer，
  Edit 工具却报 success）。**同一文件的多处编辑必须串行，改完立刻 grep 校验。**

## 补充：长期保存「已答题的数据」（store.answers）

- 用户反馈"只是保留了进度，没有保存已经答题的数据"。
- 诊断结论：本轮会话的答题内容**其实已随 session 恢复**。诊断脚本验证过：刷新后跳回第 1 题，
  `.opt.correct` / `.opt.locked` / `.feedback` 与答完时完全一致，填空题输入框也回填了 value。
  真正缺的是**跨练习轮次、跨会话的长期留档**——本轮结束或开新的一轮后，
  只剩 `store.stat` 的 done/right 计数，看不到"这道题我上次答了什么"。
- 实现：`store` 新增 `answers: { [qid]: { val, ok, t } }`，记录每题**最近一次**作答详情。
  - 写入点：给 `recordStat(id, ok, val)` 加第三个参数统一收口，`submitAnswer` 与 `finishExam` 都传入
    （val 是数组时先 slice 拷贝）。
  - 回显：新增 `answerText(q, val)` + `renderLastAnswer(q)`，题干下方显示
    "上次作答：**A. xxx**　✓ 正确　9月10日 18:03"；本轮已答则不显示（直接看本次反馈）；
    考试模式不显示（避免变相泄题）。判断题答案文本本身就是"正确/错误"，后缀只补 ✓/✗ 不重复。
  - 清空：`btnReset` 一并清 `store.answers` 与 `store.session`。
  - 云同步：`auth.js` 的 `applyServerData` 里 `answers` 采用**按题合并**策略（每题取 `t` 较新的一份），
