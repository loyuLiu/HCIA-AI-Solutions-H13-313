## 题库去重（1022 → 965 题）

### 背景与根因
用户要求「全面分析题库，去掉重合的题」。分析发现重合是**结构性**的：
每章文件都是 `判断 → 单选 → 多选 → 填空 → 补充题` 五段，后加的「补充题 / 填空题」
大量复述前面判断、单选已考过的同一事实（例如 Batch Normalization 一个知识点
同时存在 2 道判断 + 2 道填空，共 4 道题）。

### 查重方法（关键：填空要回填答案再比）
单纯比题干漏判严重。有效做法是构造「事实陈述」再比对：
- 填空：把 `____` 用标准答案回填，还原成完整陈述句
- 单选：题干 + 正确选项文本
- 多选：题干 + 所有正确选项文本
- 判断：题干本身
然后用**字符二元组 Dice 系数**算相似度（先全角转半角、去所有空白/标点/符号、转小写）。
阈值 0.85 效果最好：0.92 太松漏掉换题型复述，0.78 开始误伤（如 RNN/GNN 缩写被判重合）。

### 保留策略
同一事实簇内保留「考查强度」最高的：多选(5) > 单选(4) > 填空(3) > 判断·说法错误(2) > 判断·说法正确(1)。
（判断 a=0 答案直接写在题干里，重合时最弱。）

### 执行结果
- 删除 57 题（判断 -40、填空 -9、单选 -4、多选 -4）→ 965 题
- 各章：138 / 151 / 204 / 176 / 71 / 100 / 47 / 78

- 用户选择：**标准清理** + **不补充新题**（接受题数低于 1000）
- 清理后复检：0.85 阈值下仅剩 1 对（RNN/GNN 缩写，已人工判定为不同事实并强制保留）

### 重要：给每题固化 uid（防止进度错位）
题目 id 原本是**按位置生成**的（`ch.id + "-" + (i+1)`），删题会让后面所有题 id 前移，

- app.js:299（章节进度 `ids` 处）
`validate.js` 同步改用 uid，并新增**缺 uid / uid 重复**两项校验。

## 考试：上一题按钮 + 选项选中态 + 交卷前可改答案
